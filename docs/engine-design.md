# Prophets 匹配引擎 - 接口设计决策

## 决策记录

### 数据加载方式

**选择**：匹配引擎不内部加载数据文件，数据由调用方以 `dict[str, np.ndarray]` 形式传入。

**理由**：
1. 纯函数：引擎只做计算，不耦合文件系统
2. 灵活性：上层可以选择从 JSON、数据库、API 等任何来源加载
3. 可测试性：单元测试无需依赖磁盘文件
4. 批处理友好：一次加载后批量计算

**替代方案**（已拒绝）：
- 内部加载 JSON：耦合文件系统，难以单元测试
- 数据库直连：过度耦合，不同项目需求不同

### 匹配结果结构

**选择**：`MatchResult` dataclass 包含 `name`, `similarity`, `score`。

**理由**：
1. `name`：人物标识
2. `similarity`：余弦相似度（已四舍五入）
3. `score`：原始分数（用于需要原始精度的场景）

### 差距分析阈值

**选择**：两级阈值（0.2 和 0.5）。

**理由**：
1. 简单易懂：基本相当 / 略微 / 显著
2. 适合人格特质：人格量表通常 0-1 范围，0.2 差异已具感知
3. 可配置：如需要可改为参数传入

## 未来扩展

- 支持其他相似度度量（Jaccard、Manhattan）
- 批量分析（一次对比多个人物）
- 维度权重（不同维度重要性不同）
